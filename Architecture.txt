🔌 Backend API Structure

Auth
  POST   /api/auth/login
  POST   /api/auth/logout

NOTE: none of the paths sketched here were built as drawn. Routers are
grouped by MODULE, not by resource, and there is no /api/reports router
at all. The real layout:

  /api/auth       login, me, change-password
  /api/inventory  medicines, batches, suppliers, categories, manufacturers
  /api/billing    invoices, customers, daily-summary, gst-report
  /api/users      user management

Full endpoint list, with query parameters and failure modes:
docs/04-api-reference.md


🗄️ Key Database Tables

medicines        → id, name, category, manufacturer, HSN_code, unit
batches          → id, medicine_id, batch_no, expiry_date, purchase_price, selling_price, stock_qty
customers        → id, name, phone, address
suppliers        → id, name, contact, GST_no
invoices         → id, customer_id, date, total, discount, GST, net_amount, payment_mode
invoice_items    → id, invoice_id, batch_id, qty, price, discount
purchases        → id, supplier_id, date, total
purchase_items   → id, purchase_id, batch_id, qty, cost_price
